## CEFR/content and frequency decision

The Council of Europe defines CEFR proficiency descriptors and publishes the 2020 Companion Volume, including French-language editions; it does **not** publish one official fixed A1/A2 French word list. A1/A2 content should therefore be a documented product curriculum: derive thematic units from the descriptors (identity, family, routine, time, food, places, simple transactions), then use a frequency source/corpus and human review to select lemmas, phrases, gender, inflections and example sentences. Label it “CEFR-aligned” or “A1/A2-oriented”, not “the official CEFR vocabulary”.

Sources: [Council of Europe CEFR levels](https://www.coe.int/en/web/common-european-framework-reference-languages/level-descriptions), [CEFR Companion Volume and language versions](https://www.coe.int/en/web/common-european-framework-reference-languages/cefr-companion-volume-and-its-language-versions), [official descriptor search](https://www.coe.int/fr/web/common-european-framework-reference-languages/cefr-descriptors-search). The Companion Volume describes A1 as a basic repertoire for concrete situations and A2 as sufficient vocabulary for basic/survival needs; those are descriptors, not a word-count guarantee.

## Final engineering decision

1. Keep the current app’s learning records and review writes behind a local `reviewScheduler` adapter. Implement deterministic baseline scheduling first; optionally vendor only the `ts-fsrs` scheduler after testing the exact cloud-function Node runtime and client bundle. Pin the version and retain MIT attribution.
2. Do not import Anki, AnkiDroid, Lute, LibreLingo, Polycloze, eSpeak NG or Piper source into the mini-program. They are design references, or server/offline tooling, and GPL/AGPL material is reference-only.
3. Use native Canvas/CSS for the first streak/heatmap. Consider `@antv/f2-canvas` only if native primitives cannot meet the approved chart scope; measure bundle and device performance before adding it.
4. Keep French content as versioned JSON with source/provenance fields and a review status. Build A1/A2-oriented units from CEFR descriptors plus a named frequency source; never claim an official fixed CEFR French vocabulary list.
5. For audio, prefer pre-generated, reviewed assets. If SIWIS/Piper is used, store model-card URL, dataset credit, speaker/voice ID and CC BY attribution beside each asset. Do not bundle GPL Piper/eSpeak binaries in the client.

## Risks / open checks

- WeChat cloud-function Node version and client bundling rules must be tested before adopting `ts-fsrs` despite its browser/UMD output.
- IPA data coverage, liaison/context variants and inflections require human review; missing IPA must degrade gracefully.
- Piper engine license and each voice/model/dataset license are separate. SIWIS attribution is required; verify the exact downloaded model card and terms before publication.
- TTS quality, latency, storage/CDN cost and user consent need a real-device test; this document does not claim runtime or deployment validation.
- GPL/AGPL projects above are intentionally not direct dependencies. This is an engineering/licensing boundary, not legal advice.
